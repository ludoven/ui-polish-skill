# Web 静态高保真复刻流程

用于用户提供截图、设计图或页面捕获，并要求用最终 Web 技术栈进行 1:1、像素级、原尺寸或静态高保真复刻的场景。

## 触发边界

进入复刻模式：

- 用户明确说“复刻”“还原”“一模一样”“1:1”“像素级”“原尺寸”或“静态高保真”。
- 目标产物是可运行的 Web 页面，而不是生成一张相似图片。

不要进入复刻模式：

- “参考这个截图优化”只表示优化现有页面。
- “借鉴这个页面风格”只表示提取视觉语言。
- “审查这个截图”只表示输出问题和建议。

如果用户只说“参考截图实现”，无法判断是风格参考还是高保真复刻时，只问这一个问题：

```text
你希望只参考它的视觉风格，还是按截图尺寸做静态高保真复刻？
```

## 开始前确认

优先从截图、仓库和现有配置中识别，不要重复询问可以自行查明的信息：

- 原始截图像素尺寸。
- 目标浏览器视口的 CSS 宽高。
- 设备像素比 DPR 和浏览器缩放比例。
- 最终技术栈、页面入口和最快预览命令。
- 已有 Theme、CSS variables、Tailwind 配置、组件库和字体声明。
- 图片、图标、字体等素材能否从用户输入或仓库取得。
- 第一阶段允许修改的文件和明确禁止触碰的业务范围。

截图像素尺寸不等于 CSS 视口尺寸。只有在 DPR 为 1 时二者通常一致。无法确定 DPR 时，先给出推断依据并标记为待确认项。

## 第一阶段：静态高保真复刻

### 1. 拆解截图

按可验证的结构记录：

- 页面区域、容器层级和视觉轴线。
- 各区域尺寸、间距、对齐和溢出方式。
- 字体家族、字号、字重、行高和字间距。
- 背景、文本、边框、状态色、圆角和阴影。
- 图片裁切方式、图标风格和素材缺口。
- 截图中明确可见的静态状态。

不要仅凭截图虚构 DOM 语义、组件库来源或不可见交互。

### 2. 使用最终技术栈实现

- 直接修改最终项目或用户指定的正式实现目录。
- 复用现有组件、Token、字体和资源管线。
- 第一阶段只实现截图对应视口和静态状态。
- 不接接口、数据库、权限、路由和复杂状态流，除非用户已明确要求第一阶段包含这些内容。
- 不创建确认后会被丢弃的平行原型。
- 保持组件结构可扩展，使第二阶段能在同一份代码上继续。

### 3. 生成同尺寸浏览器截图

- 使用目标 CSS 视口、DPR 和 100% 浏览器缩放。
- 等待字体、图片和必要静态资源加载完成。
- 保证截图页面处于确定状态，不受随机数据、时间或动画影响。
- 至少输出一张与目标视口对应的完整截图。

### 4. 对比并修正

最低要求是原图与实现截图并排检查；工具允许时增加半透明叠加或像素差异图。

按以下优先级修正：

1. 页面尺寸、主容器和大区域几何。
2. 视觉轴线、模块位置和间距。
3. 字体、行高、换行和文本基线。
4. 图片裁切、图标尺寸和素材准确性。
5. 颜色、边框、圆角、阴影和微小装饰。

不要为了追逐少量抗锯齿像素差异破坏语义结构、可维护性或跨浏览器稳定性。

### 5. 第一阶段交付与暂停

交付时说明：

```text
静态复刻状态：
- 目标视口：
- DPR / 浏览器缩放：
- 使用技术栈：

已完成：
1.
2.

视觉验证：
- 原图：
- 实现截图：
- 对比方式：并排 / 叠加 / 像素差异

仍需确认：
1.
2.

阶段门禁：
- 当前未接入的响应式、交互、真实状态和业务：
- 等待用户视觉确认后继续。
```

随后停止产品化扩展。用户要求继续修正时留在第一阶段；只有明确确认后才进入第二阶段。

## 第二阶段：确认后产品化

可接受的确认包括“视觉确认”“静态复刻没问题”“继续补响应式和交互”或语义等价的明确授权。

进入第二阶段后：

1. 继续修改第一阶段的同一份代码，不从头重写。
2. 按用户范围补响应式断点、窗口缩放和移动端布局。
3. 补 hover、focus-visible、pressed、disabled、loading、empty 和 error 状态。
4. 接入用户明确授权的路由、数据和业务交互。
5. 对截图未展示的行为使用项目现有模式；没有现有依据时列出假设。
6. 在目标视口重新截图，确认产品化改动没有破坏视觉基线。
7. 验证至少一个额外关键视口；具体视口由产品目标决定。

## 验收清单

第一阶段：

- 目标视口、DPR 和缩放已记录。
- 使用的是最终技术栈和可继续维护的代码。
- 主布局、间距、字体、图片和颜色已经对照检查。
- 已生成同尺寸浏览器截图。
- 截图无法证明的行为已经标注。
- 用户确认前没有擅自进入产品化阶段。

第二阶段：

- 使用第一阶段同一份代码继续实现。
- 响应式、交互和状态范围与用户授权一致。
- 业务接入没有无关扩张。
- 已确认目标视口视觉没有回退。
- 已验证至少一个额外关键视口及必要交互状态。

## 禁止事项

- 不用生成图片代替可运行的 Web 实现。
- 不把一次性 HTML 原型当作最终项目实现。
- 不在用户确认前擅自接入业务或扩展完整功能。
- 不从单张截图臆造所有响应式和交互规则。
- 不声称“一模一样”却不记录视口、DPR 和对比证据。
- 不为像素差异引入大依赖或破坏项目既有设计系统。
