# UI 设计实现与代码修改流程

用于用户要求根据截图或 UI 设计稿实现新界面、直接优化已有页面、按审查报告改代码，或只改 UI 不改业务逻辑的场景。

## 实现前确认

实现前先确认或搜索：

- 是否已有 UI 审查报告。
- 要新建或修改的页面、组件、入口或截图位置。
- 技术栈和目标平台。
- 设计稿对应的视口、设备尺寸或窗口形态。
- 是否存在 Design Tokens、Theme、Color、Typography、Spacing、Radius、组件库。
- 当前页面的真实入口、预览方式或最快验证命令。

如果项目已有设计系统，优先复用，不另造平行 token。

## 编辑前计划

动手前说明 3-6 条计划，明确文件和原因：

```text
准备修改：
- 文件 A：调整布局和间距。
- 文件 B：复用/补充 token。
- 文件 C：统一组件状态。
验证：运行最快相关检查或截图复查。
```

## 设计稿实现流程

当用户提供 UI 设计稿并要求实现新界面时：

1. 定位目标模块、技术栈、页面入口、Theme、组件库和预览方式。
2. 从设计稿提取页面结构、布局约束、尺寸关系、字体层级、颜色、图标、素材和可见状态。
3. 区分设计稿明确内容与推测内容；无法从设计稿判断的交互、滚动、响应式和业务状态列为假设或待确认项。
4. 复用已有 Design Tokens 和组件；缺少时只补实现当前页面所需的最小集合。
5. 在目标技术栈中创建必要的页面和 UI 组件，不另建会被丢弃的演示技术栈。
6. 复用现有数据和状态入口；未提供业务数据时使用隔离的预览或展示数据，并明确说明，不伪造接口和真实业务逻辑。
7. 缺少图标、图片或字体素材时先搜索项目；仍缺失时使用明确占位并列出待补素材。
8. 运行最快的编译、预览或截图验证，并检查目标尺寸下的布局差异。

只有用户明确要求 1:1、像素级、原尺寸或静态高保真 Web 复刻时，才切换到 `replication-playbook.md` 的两阶段门禁流程。

## 实现边界

必须遵守：

1. 只修改 UI 层。
2. 不改接口、数据模型、路由、数据库、权限、状态流和核心业务逻辑。
3. 不新增复杂功能。
4. 不引入新的大依赖。
5. 不使用强阴影、大面积渐变、卡片套卡片来制造质感。
6. 不随意加入玻璃拟态、霓虹色或复杂动效。
7. 所有颜色、字号、间距尽量走现有设计系统或集中 token。
8. 优化已有页面时保持小步 diff；从设计稿新建页面时只创建必要的 UI 结构。
9. 不删除业务功能。
10. 如果业务代码和 UI 强耦合，只做最小必要调整并说明原因。

## 推荐修改顺序

1. 定位真实 UI 文件和主题文件。
2. 复用或补齐 Design Tokens：
   - Color
   - Typography
   - Spacing
   - Radius
   - Icon size
   - Component height
   - State layers
3. 调整页面布局：
   - 页面 padding
   - 模块顺序
   - 视觉焦点
   - 内容密度
   - 响应式/窗口尺寸
4. 统一字体层级：
   - 页面标题
   - 模块标题
   - 正文
   - 辅助文字
   - 标签
5. 统一颜色：
   - 背景
   - 容器
   - 文本
   - 分割线
   - 状态色
6. 删除廉价设计元素：
   - 多余卡片
   - 强阴影
   - 大渐变
   - 多余边框
   - 图标底板
7. 统一图标和操作控件：
   - 尺寸
   - 线宽
   - 颜色
   - 对齐
   - 可点击区域
8. 补齐状态：
   - loading
   - empty
   - error
   - disabled
   - selected
   - hover/focus/pressed
9. 最后才考虑动效：
   - 只保留必要状态反馈。
   - 不做炫技动画。

## 代码策略

- 优先替换硬编码颜色、字号、间距为已有 token。
- 如果没有 token，可在现有 theme 文件中补最小集合，不单独新建庞大设计系统。
- 组件结构调整要保持交互能力不变。
- 列表、表格、工具栏优先优化密度和对齐，不要都包成卡片。
- 移动端优先检查 safe area、触控目标和文本溢出。
- 桌面端优先检查窗口尺寸、键盘焦点、hover、菜单/工具栏关系和高密度列表。
- Web 优先检查响应式断点、focus-visible、语义结构和长文案。
- TV 优先检查焦点环、遥控器导航、远距离字号和安全边距。

## 验证

按风险选择最快验证：

- 纯样式：类型检查、lint、编译或组件预览。
- Web：本地页面截图，至少桌面和移动视口。
- Compose/Flutter/SwiftUI：编译或预览可用时截图复查。
- 桌面端：打开窗口确认布局、hover/focus、窗口缩放。
- TV/遥控器：确认焦点顺序和焦点可见。

如果无法运行验证，说明原因和残余风险。
